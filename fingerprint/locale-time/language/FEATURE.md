# fingerprint/locale-time/language

Category: build, other, spoof

Test: `Intl_Locale_StealthSystemLocales.TheDeclaredLanguageIsTheRegionalLanguage`, `.ADeclaredLanguageOfAnotherLanguageKeepsTheAppLocales`, `.WithTheOSLocalesPreferenceTheDeclaredLanguageIsTheOnlyOne`, `.ADeclaredLanguageIsAnsweredBeforeTheOperatingSystemIsAsked`, `.TheLanguageAtomServiceAnswersAWorkersDeclaredLanguage` (gtest, `intl/locale/tests/gtest/TestStealthRegionalLocales.cpp`); `Intl_Locale_StealthSystemLocales.AWorkerThreadKeepsItsOwnDeclaredLanguage` (gtest of session-declaration); wrapper e2e `tests/test_context_locale_e2e.py::test_an_offscreen_canvas_of_a_worker_draws_with_the_language_group_of_its_context` and `::test_text_without_lang_takes_the_language_group_of_the_session_language` (to write)

## What it does

The language the session declares is the language of "the machine" for the two process-wide questions that have no context to ask: the regional locales (`LocaleService::GetRegionalPrefsLocales`, which feed the web-exposed locales, the date and time inputs and `AppDateTimeFormat`) and the language of text that declares none (`nsLanguageAtomService::GetLocaleLanguage`, which picks the font language group of a canvas without `lang`, of `nsFontCache` and of `EncodingToLang`). Both ask the host's `OSPreferences` when nothing is declared; when a language is declared the host is not asked, so a page does not measure the machine.

Only the input changes. The rule of `GetRegionalPrefsLocales` stays Mozilla's: the regional language is used only when it matches the app locale (a real en-US build on a de-DE machine formats as en-US), so a declared `ja-JP` in an en-US build leaves the app locales. When nothing is declared (the engine launched without the core) every caller keeps Firefox's own path.

The atom is one per process, cached under `mLock` at the first call; a worker thread asks first for the language its realm carries (`WorkerLocaleLanguage`, a thread-local set at the birth of the realm), so an OffscreenCanvas in a worker of a context with its own language draws with that context's language group. A second context with its own language keeps the session's language for the main thread's layout and canvas.

The logic is in `intl/locale/StealthSessionPrefs.cpp` (folder `fingerprint/locale-time/session-declaration`): `StealthDeclaredRegionalPrefsLocales` (in namespace `mozilla::intl`: when a language is declared, the declared tag as the only entry and the answer true; when nothing is declared, false with the list left as it was), `SessionLocaleLanguage` (the declared tag as a lowercase atom, else null), `WorkerLocaleLanguage`.

## Hooks in Mozilla files

- `intl/locale/nsLanguageAtomService.cpp`: registration, an include of `StealthSessionPrefs.h` in a block of ours after Mozilla's includes; guard, first statement of `GetLocaleLanguage`: `if (nsAtom* worker = intl::WorkerLocaleLanguage()) return worker;` (the name has no `Stealth` prefix because the gtests of session-declaration call it, G41; the guard has an initializer because the result is the return value); anchor, inside `if (!mLocaleLanguage) {` before the OS lookup: `if ((mLocaleLanguage = intl::SessionLocaleLanguage())) return mLocaleLanguage;`. The anchor is an approved exception: it is a mid-function branch inside Mozilla's lazy initialisation under the write lock, which no guard or wrap of the function expresses without running Mozilla's initialisation first.
- `intl/locale/LocaleService.cpp`: registration, an include of `StealthSessionPrefs.h` in a block of ours after Mozilla's includes; Mozilla's `OSPreferences::GetInstance()->GetRegionalPrefsLocales` calls stay as Mozilla wrote them, and two anchors of ours decide first. The first, as the first statement of Mozilla's `if (useOSLocales) {`: `if (StealthDeclaredRegionalPrefsLocales(aRetVal)) return NS_OK;` (it answers only when the OS regional preferences are used; `OSPreferences` has two other callers, `Troubleshoot.sys.mjs` and `TelemetryEnvironment.sys.mjs`, which keep the host's value, so the declaration is not applied at the source, and a guard at the head of the function would also answer when the preference is off). The second, an unbraced `if (!StealthDeclaredRegionalPrefsLocales(regionalPrefsLocales))` right after `LocaleService::GetInstance()->GetAppLocaleAsBCP47(appLocale);` and before Mozilla's untouched `if (NS_FAILED(OSPreferences::GetInstance()->GetRegionalPrefsLocales(...)))`: it conditions Mozilla's host query, so the host is not asked when a language is declared and the declared list goes through Mozilla's language match (`regionalPrefsLocales` is Mozilla's local, declared a few lines above, so a guard at the head of the function would run before it exists).
- `intl/locale/moz.build`: registration of `StealthSessionPrefs.h` and `StealthSessionPrefs.cpp` (marker of session-declaration, which owns the files).
- `intl/locale/tests/gtest/moz.build`: registration of `TestStealthRegionalLocales.cpp`.

## Tests

`TestStealthRegionalLocales.cpp` goes through `LocaleService::GetRegionalPrefsLocales`, the entry every caller uses: a declared `en-TT, en, en-US` is the only regional locale (the control with nothing declared is not `en-TT`); a declared `ja-JP` leaves the app locales (Mozilla's rule); with `intl.regional_prefs.use_os_locales` the declared `ja-JP` is the only locale (control: not `ja-JP` with nothing declared). The atom of the first call is not tested in-process: the service caches it for the life of the process.

`ADeclaredLanguageIsAnsweredBeforeTheOperatingSystemIsAsked` calls `StealthDeclaredRegionalPrefsLocales` on a list holding a sentinel: with a language declared the list is that language alone and the answer is true; with nothing declared the answer is false and the list is untouched, so Mozilla's call fills it. `TheLanguageAtomServiceAnswersAWorkersDeclaredLanguage` asks `nsLanguageAtomService::GetLocaleLanguage` from a worker thread that carries a declared language.

The gtest passes an empty list to `GetRegionalPrefsLocales` (Mozilla's function wants one) and leaves no state in the process: nothing it declares or caches outlives a test.
