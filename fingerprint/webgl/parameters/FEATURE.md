Category: spoof

## What it does

A WebGL context tells the page what the session declares, not what the host GL is: `getParameter` (numbers, renderer, vendor), `getShaderPrecisionFormat`, the list of extensions (decided once, in `MakeLimits`, so the page reads it in Firefox's own enum order) and the host's defences for an extension the persona declares and the host does not serve. Every function reports "not overridden" when its pref is empty and Mozilla's code runs as it is.

`dom/canvas/ClientWebGLContext.cpp` also carries the hooks of the canvas noise (fingerprint/canvas/noise-projection) on the roads that read a WebGL canvas: `readPixels`, `toDataURL`/`toBlob` and `captureStream`. Their logic is in `dom/canvas/StealthWebGLReadback.h` of that folder; the marker of those hooks names that folder, because the called function lives there.

## Hooks in Mozilla files

All hooks are one line with the marker on the line.

- `dom/canvas/ClientWebGLContext.cpp`
  - Includes of `StealthWebGLParams.h` and `StealthWebGLReadback.h` in a block of ours after Mozilla's last include (the second header is inline and must be included in this .cpp only: the PIXEL_PACK_BUFFER road sends commands with `Run`, a template defined here).
  - **getParameter**: the RAII object `StealthWebGLParameterAnswer` (StealthWebGLParams.h) is constructed after `const auto& state = State();`, with the marker on its line; its destructor replaces the host's number with the declared one when Mozilla's body leaves, inside `FuncScope`, when the function answered with a value (not null, no failed `ErrorResult`). Mozilla decides first whether the pname exists for this context, so a WebGL2-only pname on a WebGL1 context stays null with INVALID_ENUM. The signature is the tag's.
  - **RENDERER, UNMASKED_RENDERER_WEBGL, UNMASKED_VENDOR_WEBGL**: three anchors, the first statement of their `case`, `if (StealthWebGLRendererOverride(ret)) break;` and the two others, passing Mozilla's local `ret`. They stay where they are (G28): answered from the wrapper they would run before Mozilla's computation, and for UNMASKED they would redo Mozilla's check that `WEBGL_debug_renderer_info` is enabled. The host's string is never read: the break is before Mozilla's `GetString`.
  - **getShaderPrecisionFormat** (guard, G49): `if (already_AddRefed<WebGLShaderPrecisionFormatJS> rv; StealthWebGLShaderPrecisionFormat(shadertype, precisiontype, &rv)) return rv;` right after Mozilla's lost-context check and before Mozilla reads the precisions the host reported: with a declared triple for the pair the page is answered at once (one read of the pref) and the host's table is never looked at, as on the baseline.
  - **toDataURL, toBlob** (`GetImageBuffer`, `GetInputStream`): one added line after Mozilla's `if (!snapshot)` check, `snapshot = StealthWebGLProjectReaderSnapshot(*this, snapshot, any);`, which receives the locals; the alpha type is the one Mozilla computed (`any`).
  - **readPixels into an array**: `bool succeeded = StealthWebGLProjectReadPixels(*this, desc, *range, DoReadPixels(desc, *range));` (wrap-expression; Mozilla's call runs first). **readPixels into a PIXEL_PACK_BUFFER**: `StealthWebGLReadback::ProjectReadPixelsPbo(*this, desc, offset);`, an anchor after `Run<RPROC(ReadPixelsPbo)>`, the last line of the function (G30: it needs the read to have been sent and `desc`, which Mozilla builds from the validated parameters).
  - **DoReadPixels** is Mozilla's text (two parameters). The anchor `StealthWebGLReadback::NoteReadPixels(*this, subrect, byteStride);` after the loop that copies the rows writes the two locals the projection needs, the part of the requested rectangle that lies inside the framebuffer and the row stride, into the private field `mStealthReadPixelsResult` (member line in `ClientWebGLContext.h`, fingerprint/canvas/noise-projection) (G5). `DoReadPixels` sets it whenever it returns true; the projection takes it right after the call, on the same thread, and zeroes it as it takes it; the reads the projection itself makes zero it before the call. A value left by another caller (`BackBufferSnapshot`) is overwritten before anyone reads it.
  - **captureStream** (`DoReadPixelsAsync`; wrap-expression): `promise->Resolve(StealthWebGLProjectAsyncSnapshot(*self, std::move(sourceSurface)), __func__);` wraps Mozilla's argument; the alpha type is the context's options', so Mozilla's lambda is as in the tag (no captured `premultiplied`).
- `dom/canvas/WebGLContextExtensions.cpp`: the include; in `IsExtensionSupported`, in the case of `WEBGL_provoking_vertex`, right after Mozilla's check that the GL has the feature: `if (StealthWebGLExtensionServed(this, ext)) return true;` (the declared extension is served ahead of Mozilla's per-platform policy, ANGLE or macOS only; otherwise Mozilla's policy answers). An anchor in `RequestExtension` after Mozilla's check of the limits (it stays there, G28): `StealthWebGLExtensionUnserved(this, ext)`, a declared extension the host does not serve is not created, its entry points stay harmless. The page is told the persona's list on the client side; the host decided on its own, and a declared extension it refused was a trap (2026-11-07, read with symbols on Linux: one `provokingVertexWEBGL()` call, MOZ_RELEASE_ASSERT, main process gone, no GPU process there).
- `dom/canvas/WebGLContextGL.cpp` (BlendEquationSeparate and BlendFuncSeparate with an index, PolygonOffsetClampEXT, ProvokingVertex, ClipControlEXT) and `dom/canvas/WebGLContextFramebufferOperations.cpp` (ColorMask with an index): an entry point whose extension is not enabled returns before Mozilla's assert, which stays: `StealthWebGLDrawBuffersIndexedMissing(this)` (inside `if (i)`, after the enum validation), `StealthWebGLPolygonOffsetClampMissing`, `StealthWebGLProvokingVertexMissing`, `StealthWebGLClipControlMissing` (after `IsContextLost()`, whose HandlePendingContextLoss must run first). Anchors, because a guard in the head would run before those. The include in a block of ours in both files.
- **One decision on the extension list, in the host.** `dom/canvas/WebGLContextValidate.cpp` (end of MakeLimits): `StealthDeclareLimits(webgl, &limits);`, an added line right before Mozilla's `return limits;`: `StealthDeclareExtensions` puts the declared list (`zoom.stealth.webgl.extensions` / `webgl2`) into the finished limits handed to the content process; every limit Mozilla derives from the extension bits inside MakeLimits is still computed from what the GL serves. `ClientWebGLContext.cpp` has no decision of its own: IsSupported and getSupportedExtensions read the limits, so the page gets the list in Firefox's enum order, the only order retail gives.
- `dom/canvas/WebGLContextValidate.cpp` (InitAndValidateGL, after the four `AssertUintParamCorrect`): an anchor `StealthInitStencilMasks(mStencilValueMaskFront, mStencilValueMaskBack, mStencilWriteMaskFront, mStencilWriteMaskBack);` passing the four private fields: the masks start at all ones, ANGLE's value on Windows, instead of the driver's (Mesa trims to its stencil bits: 255). What a page sets is unchanged; the driver masks to its own bits either way. It is a read of the host corrected afterwards (FINDINGS.md).

## Our own files

- `dom/canvas/StealthWebGLParams.h/.cpp`: the declared numbers (`StealthWebGLParameterOverride`, reading `zoom.stealth.webgl.int_params`, `float_params` and `int2_params`, in that order), the string answers, the shader precisions, the extension verdict and the functions named above. `StealthWebGLParameterAnswer` is the baseline's RAII class.
- `dom/canvas/StealthWebGLReadback.h` is in fingerprint/canvas/noise-projection.

## dom/canvas/StealthWebGLParams.h: StealthWebGLExtensionServed

The hook sits in the case of WEBGL_provoking_vertex, after Mozilla's check that the GL has the feature, so the function only asks whether the pref declares the extension for this context kind (the prefs are read only for that extension).
