## What it does

The caller's world of Juggler (where `page.evaluate` and the other ways of running the caller's code run) is a Cu.Sandbox with the page's own principal, created with the option `hybridXrays: true, wantXrays: false`. Only Juggler passes the option. The sandbox reads the page through hybrid Xrays: a name the standard defines is the browser's native one, whatever the page put in its place; a name the page added (a global, an expando on a node, a top-level `let`/`const`/`class`) is the page's, so a page that wraps `Document.prototype.querySelector` in a Proxy cannot count the caller's calls. The rule is written above `HybridXrayWrapper` in `StealthHybridXray.h`. In the other direction the page reads the objects the caller hands it through `CallerObjectWrapper` (`StealthHybridXray.cpp`): their own properties are shared, their standard prototypes are shown as the page's own (`arg instanceof Array` holds, `cb.constructor` is the page's Function). A cross-origin object (WindowProxy, Location) the caller hands over stays a `CrossOriginObjectWrapper`. The option needs a content principal and `wantXrays: false`; the system principal, an expanded principal and `wantXrays: true` are refused with NS_ERROR_INVALID_ARG.

## Hooks in Mozilla files

All logic is in our files: `js/xpconnect/src/StealthSandbox.h` (Sandbox.cpp side) and `js/xpconnect/wrappers/StealthHybridXray.cpp/.h` (wrappers side).

- `js/xpconnect/src/Sandbox.cpp`
  - `#include "StealthSandbox.h"` in a block of ours after Mozilla's includes (registration; it brings XrayWrapper.h through StealthHybridXray.h).
  - `SandboxProxyHandler::getPropertyDescriptorImpl`: the call `JS_GetPropertyDescriptorById` becomes `xpc::StealthGetPropertyDescriptor` with the same arguments (call wrap, G29). For a hybrid Xray prototype it resolves the bare name by the hybrid rule (`HybridXrayGetBareName`), in the order the page's realm resolves it, without running the page's traps; for any other object it is Mozilla's call. Mozilla's fix-up of accessors and callables below still runs on the result.
  - `xpc::CreateSandboxObject`, anchor right after `bool isSystemPrincipal = ...`: `if (!xpc::StealthCheckHybridXrays(cx, principal, options)) return NS_ERROR_INVALID_ARG;`; `StealthCheckHybridXrays` reports a JS error and returns false when the option is given with the system principal, an expanded principal or `wantXrays`, and true otherwise. `principal` is derived inside the function, so no guard at the top can see it.
  - `xpc::CreateSandboxObject`, two anchors, one at the end of each branch of the if/else that sets the compartment flags: `MOZ_RELEASE_ASSERT(priv->hybridXrays == options.hybridXrays);` in the reused-compartment branch (it checks, it does not write) and `priv->hybridXrays = options.hybridXrays;` in the new-compartment branch, as on the baseline (G18, G30).
  - `SandboxOptions::Parse`: the line `ParseBoolean("hybridXrays", &hybridXrays) &&` stays inside Mozilla's `&&` chain, right after `wantXrays` (declared exception, G35, approved by the pm; G28: a head guard would read `hybridXrays` before `wantXrays`, which changes the order of property reads of the options object and the error reported with two invalid options).
- `js/xpconnect/src/xpcprivate.h`: `bool hybridXrays = false;` after `bool wantXrays;` in `SandboxOptions` and in `CompartmentPrivate` (members with a default initialiser, so the constructors are Mozilla's again); `CompartmentPrivate::StealthIsHybrid()` and the guard `if (this->StealthIsHybrid()) return false;` at the head of `CanShareCompartmentWith` (a hybrid compartment is never shared; `untestable` granted by the pm: the only caller passes the compartment of a window; Mozilla's return line is as in the tag).
- `js/xpconnect/src/XPCJSRuntime.cpp`: back as in the tag (no hook).
- `js/xpconnect/wrappers/WrapperFactory.cpp` (`WrapperFactory::Rewrap`, `DEBUG_CheckUnwrapSafety`): `#include "StealthHybridXray.h"` in a block of ours. The term `targetCompartmentPrivate->wantXrays` of the cross-origin predicate, the web-objects predicate and `sameOriginXrays` is wrapped in `StealthTargetWantsXrays(cx, wantXrays)`, which adds the caller's world to the target's term (the origin keeps Mozilla's `wantXrays`: a caller's world wants Xrays when IT reads the page but does not impose them on the page reading ITS objects). ## js/xpconnect/src/xpcprivate.h: CompartmentPrivate::hybridXrays

STEALTHFOX [B322]: this compartment is a caller's world, which reads same-origin content through hybrid Xrays (the standard definition of a name the standard defines, the page's for every other name) while that content reads its objects transparently. Set only by Cu.Sandbox's `hybridXrays` option, which only Juggler passes. The rule is written above HybridXrayWrapper in StealthHybridXray.h.

## js/xpconnect/src/xpcprivate.h: SandboxOptions::hybridXrays

The `hybridXrays` option of Cu.Sandbox, false unless given (see CompartmentPrivate::hybridXrays). It replaces `wantXrays` instead of adding to it: `wantXrays` would impose Xrays on the page reading the caller's objects as well, so the option needs `wantXrays: false` and a content principal.
